> 「**適用除外により資金決済法上の払戻義務がないからこそ**、規約で自主的に
> 手当てしておかないと、消費者契約法10条・不当利得の争点として残ります。」

**実装で対応したのは1件**: コインの消費順序を**期限の早い順**に改めた(`0082`)。
旧実装は「有償を先に使い切る」順序で、複数回購入すると**期限順なら失効しなかった
はずの無償コインが失効**した。指摘は消費者契約法10条ではなく
**景品表示法5条2号(有利誤認)** — 「ボーナス+100」と表示して購入を誘引しながら、
仕組みの側でボーナスを失効させるのは説明しづらい、というもの。

**新たに恒久的な制約が4つ増えました**(同記録の末尾)。特に:

- **報酬コインをサービス内の支払いに使えるようにしない**(資金決済法の整理が根元から揺らぐ)
- **あんしんサポート料を損失填補の原資と説明しない**(自ら保険構成を招く)

### App Store に出すかどうか(2026-07-29 の判断: **出さない**)

Appleの手数料は総額にかかり、ピタフレの取り分は差分にしかかからないので、
**率が近くても算数が合いません。**ゲストが1万円払った予約1件あたり:

| ピタメイトの段階 | PFの取り分 | Apple 15%(Small Business)後 |
|---|---:|---:|
| 第1段階 20% | ¥2,000 | ¥500 |
| 第2段階 17% | ¥1,700 | ¥200 |
| 第3段階 14% | ¥1,400 | **−¥100** |
| 第4段階 12% | ¥1,200 | **−¥300** |
| リピート割の下限 10% | ¥1,000 | **−¥500** |

**育ってほしいピタメイトほど赤字が深くなる**ため、IAPを載せる形は
手数料モデルを作り直さない限り選択肢に入りません。競合(GameRoom ギフト35% /
PLAYONE 注文40%・実効約50%)が高率なのは、IAPを載せるとそれ以下では回らないからです。

将来出すなら **コインをアプリ内で売らない形**(予約・チャットのみ、購入はWeb)で、
かつ課題が獲得ではなく通知の到達率になってから。その際は次を先に確認すること:

- スマホソフトウェア競争促進法(2025年12月完全施行)下で、Appleが日本の
  外部課金・外部リンクに**別途手数料を課していないか**(EUでは課した)
- 審査ガイドライン 3.1.1(アプリ内通貨)と 1.1.4(出会い系)の判定リスク。
  ピタフレは法的に出会い系非該当だが、**Appleの審査基準は法律とは別**

### 【要対応】キャンセルポリシーの表示が実態と食い違っている(E-10)

E-1/E-2 の実装中に判明しました。**予約画面・トーク画面のキャンセル確認・
規約第9条・特商法表記のいずれもが、実際には起きない条件を説明しています。**

- 表示: 「あなたの都合のキャンセル → **開始1時間前まで全額再付与**」
- 実態: **ホストが承諾した瞬間から100%没収**。承諾の0秒後にキャンセルしても戻らない

原因は、本サービスに**将来日時を指定する予約が無い**ことです。ホストが申込みを
承諾した時点が役務の開始時刻になる(`approve_booking` が開始時刻に現在時刻を入れる)
ため、判定式「現在時刻 < 開始時刻 − 1時間」が承諾後つねに偽になります。
テスト環境で承諾直後にキャンセルし、1,000コインが没収されることを確認済みです
(`supabase/tests/30_cancellation_evidence.sql`)。

該当箇所は次の4つです。

| 場所 | 現在の表示 |
|---|---|
| `src/screens/Booking.tsx` | あなたの都合のキャンセル → 開始1時間前まで全額再付与 |
| `src/screens/Talk.tsx`(キャンセル確認) | 開始1時間前まではコインが全額戻ります |
| 規約 第9条の表 | ゲスト都合のキャンセル(開始1時間前まで) → 全額再付与 |
| 特商法表記 | 規約第9条を参照する形 |

**トーク画面のキャンセル確認が特に影響が大きい**です。まさに取り消そうとしている
瞬間に「1時間前までは全額戻る」と読ませており、実際には戻りません。

なお承諾**前**(ホストが応答する前)のキャンセルは全額返金されるので、
「一切返らない」わけではありません。

**申込前の表示が事実と異なる**状態なので、公開前に必ず是正が必要です。ただし
直し方が3通りあり、どれを採るかで文言が変わるため **Q14-b/c の回答待ち**にしています。

- (ア) 承諾後に無料キャンセルの猶予(例: 5〜10分)を設ける → 表示に実態を寄せる
- (イ) 経過時間に応じた按分返金にする
- (ウ) 現行のまま100%没収とし、表示のほうを実態に合わせて書き換える

### E-8 の対象範囲について(ギフト受領コインは含まない)

「ギフトとして受領したコインも同じ起算問題を持つのでは」という点を実装で確認した

`coin_lots`(発行日と期限を持つロット)は作られません。`earned_balance` の減少経路は

の対象外です。したがって E-8 の修正スコープは**返金(再付与)経路のみ**です。

> **報酬コインも含まれてしまいます**。一方で実装上、報酬コイン(`earned_balance`)には
> 有効期限がありません。実装のほうがユーザーに有利ではあるものの、**規約と実装が
> 食い違っている**ので、条文側で「報酬コインには適用しない」と書き分ける必要が
> あります。Q18の枝問として確認します。
