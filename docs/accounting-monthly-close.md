# 月次の締め作業（ピタフレ専用）

- 作成: 2026-07-30
- 対象: 事業主本人（ワンオペ）
- 所要: 慣れれば **30〜40分/月**
- 関連: `docs/separate-account-policy.md` 第8条（月次照合）／`docs/tax-startup-record.md`

> **この文書の狙いは「毎月ゼロから考えない」ことです。**
> 会計は、判断が要るのは最初の一度だけで、あとは同じ作業の繰り返しになります。
> 繰り返しの部分をアプリ側に寄せて、**手で判断する項目を最小にしてあります。**

## 0. 自動化した範囲と、していない範囲

**「全部自動」とは言えません。** どこまでが自動かをはっきりさせておくほうが、
抜けに気づけます。

| | 誰が出すか | 手作業 |
|---|---|---|
| コイン購入・予約・報酬確定・利用料・換金・失効 | **アプリが仕訳まで生成** | CSVを取り込むだけ |
| 仕訳と元帳の突合 | **アプリが判定** | 見るだけ |
| ピタメイト別の年間支払額 | **アプリが集計** | 保存するだけ |
| Stripeの着金と決済手数料 | Stripeの明細 | **月1回・2〜3行** |
| 経費（サーバー・ドメイン・ソフトウェア利用料） | 領収書・クレカ明細 | **都度** |
| 通信費・電気代の家事按分 | `docs/templates/家事按分メモ.md` | **年1回** |
| 開業費の償却 | `docs/tax-startup-record.md` | **年1回** |

**アプリが出せるのは「アプリの中で起きたこと」だけです。**
銀行口座とクレジットカードで起きたことは、アプリからは見えません。

## 1. 手順（毎月1回・前月分）

### 1-a. 運営コンソール →「会計」タブを開く

期間は初期値が**前月**になっています。締めは前月分を扱うので、通常は触りません。

### 1-b. まず「仕訳と元帳の突合」を見る

**ここが赤ければ、この先へ進んではいけません。**

| 判定 | 意味 |
|---|---|
| すべて OK | 仕訳を全部足した結果が、元帳の残高と一致している |
| いずれかが NG | 仕訳の生成漏れか、関数を通さない残高の書き換えがある |

差額が出た状態のCSVを取り込むと、**帳簿が狂ったことに数か月気づけません。**
そのため NG のときは仕訳CSVのボタン自体が押せないようにしてあります。

> この突合は「開業日から今日まで」の**累計**で見ています。
> 月だけを切り出すと、前月から繰り越した残高のぶんだけ必ずずれます。

### 1-c. 4つのCSVを落とす

| ファイル | 用途 |
|---|---|
| 仕訳 | **会計ソフトの汎用仕訳インポートに取り込む**（「純額処理で出力する」は初期値のオンのまま） |
| 残高 | 第8条の照合の証跡として保存 |
| 売上 | 売上の内訳を目視で確認 |
| ピタメイト別支払額 | 年間の支払額の記録（年1回でも足りるが、毎月落としておくと安全） |

CSVはBOM付きUTF-8・CRLFです。Excelでも会計ソフトでもそのまま開けます。

### 1-d. 会計ソフトに取り込む

列は次の並びで出ます。ソフト側のインポート設定は**初回に一度作れば以後は使い回せます。**

```
日付, 借方勘定科目, 借方補助科目, 借方金額, 借方税区分,
      貸方勘定科目, 貸方補助科目, 貸方金額, 貸方税区分, 摘要
```

- **1行が「借方1・貸方1・金額1」**（単純仕訳）です。複合仕訳は出しません。
  取込形式がソフトごとに割れるうえ、1行ずつ貸借が合っているかを目で追えなくなるためです。
- 金額は **1コイン＝1円**。
- 税区分は弥生の名称（`課対売上込10%` / `対象外`）で出しています。
  freee・マネーフォワードはいずれも弥生形式を取り込めます。
  **不課税取引（コイン失効益）は、会計ソフト上は「対象外」で入力します。**

### 1-e. Stripeの明細から、着金と決済手数料を起票する

**ここだけは手で入れます。** アプリは「未収入金／Stripe」までしか作れません
（DBにStripeの入金データが無いため）。

Stripeダッシュボード →「残高」→ 入金（payout）ごとに、

```
借）普通預金（分別口座）  実着金額     / 貸）未収入金（Stripe）  総額
借）支払手数料           差額（手数料）
```

月に2〜3行で済みます。

### 1-f. ★Stripeの取引明細をCSV/PDFでエクスポートして保存する

**電子帳簿保存法。これを飛ばさないこと。**

> 税理士 Q15-c:「Stripe側のデータは解約すると失われます。
> **これは締め作業に組み込む以外の方法では、必ず忘れます。**」

保存先: 〔　　〕（`docs/separate-account-policy.md` 第11条の保存場所と同じ）

### 1-g. 経費を入れる

領収書・クレジットカード明細から。当面は月に数件です。

| 科目 | 中身 |
|---|---|
| 通信費 | 回線（**按分後**） |
| 水道光熱費 | 電気代（**按分後**） |
| 支払手数料 | Stripe決済手数料（1-e で入力済）、銀行の振込手数料 |
| ソフトウェア利用料 | Anthropic、その他のSaaS |
| 広告宣伝費 | X Premium 等 |
| 通信費／支払手数料 | ドメイン、Cloudflare、Supabase |

### 1-h. 第8条の照合を記録する

「会計」タブの**残高**を見て、次の4つを確認し、記録に残します。

1. 前受金（コイン）＝ 有償コインの未使用残高 × 1円
2. 預り金（ピタメイト報酬）＝ 報酬コイン残高 × 1円
3. 分別口座＋支払口座の残高 ≧ **分別対象額（第4条）**
4. **「要確認・期限切れ・失効処理待ち」が 0 であること**

> 4が0でなければ `expire_coins()` が動いていません（＝雑収入の計上漏れ）。
> pg_cron を確認してください。

## 2. 出てくる仕訳の一覧

アプリが生成する仕訳はこれで全部です。**知らない科目が出てきたら、
それは仕様変更が入ったということなので、税理士に確認してください。**

| 事象 | 借方 | 貸方 | 税区分 |
|---|---|---|---|
| コイン購入（コイン代金） | 未収入金／Stripe | 前受金／コイン | 対象外 |
| コイン購入（サポート料） | 未収入金／Stripe | 売上高／あんしんサポート料 | 課対売上込10% |
| 無償コインの付与 | — | — | **廃止（`0083`）。**以下「無償」の行はすべて0になります |
| 予約成立（有償分） | 前受金／コイン | 前受金／予約エスクロー | 対象外 |
| 予約成立（無償分） | **販売促進費／無償コイン ★** | 前受金／予約エスクロー | 対象外 |
| 返金（有償分） | 前受金／予約エスクロー | 前受金／コイン | 対象外 |
| 返金（無償分） | 前受金／予約エスクロー | 販売促進費／無償コイン | 対象外 |
| 報酬確定（完了・キャンセル没収） | 前受金／予約エスクロー | 預り金／ピタメイト報酬 | 対象外 |
| ギフト受領 | 前受金／コイン | 預り金／ピタメイト報酬 | 対象外 |
| プラットフォーム利用料 | 預り金／ピタメイト報酬 | 売上高／PF利用料 | 課対売上込10% |
| 換金申請（振込予定額） | 預り金／ピタメイト報酬 | 預り金／換金申請中 | 対象外 |
| 換金申請（事務手数料） | 預り金／ピタメイト報酬 | 仮受金／換金手数料 | 対象外 |
| 振込完了 | 預り金／換金申請中 | 普通預金／支払口座 | 対象外 |
| 換金事務手数料の売上振替 | 仮受金／換金手数料 | 売上高／換金事務手数料 | 課対売上込10% |
| 振込失敗の戻し | 預り金／換金申請中・仮受金 | 預り金／ピタメイト報酬 | 対象外 |
| コイン失効（有償） | 前受金／コイン | 雑収入／コイン失効益 | 対象外（不課税） |
| コイン失効（無償） | — | — | **仕訳なし**（前受金を立てていない） |
| **純額調整**（下記★） | 売上高／PF利用料 | 販売促進費／無償コイン | 課対売上込10% |

### ★ 無償コイン関連の行は、当面すべて0になります

**2026-07-31 に購入ボーナス（上乗せコイン）を廃止しました（`0083`）。**
無償コインが新たに発生しないため、上の表の次の行は**すべて0**になります。

- 予約成立（無償分）／返金（無償分） … 販売促進費
- 純額調整

**行そのものは残してあります。** 消していないのは、
①**0が出ることが「発生していない」ことの確認になる**ため（行ごと消すと、
再開したときに気づかず両建てのまま記帳してしまう）、②再開の判断があったときに
仕組みを作り直さずに済むため、の2つです。

**チェックボックス「純額処理で出力する」は、初期値オンのままにしておいてください。**
対象が0件なので出力は変わりませんが、再開したときに自動で効きます。

<details><summary>廃止前の整理（再開する場合はここに戻る）</summary>

無償コインで予約が成立したとき、ピタメイトへの支払は発生するのに現金は
1円も受け取っていません。前払金を立てていない以上、どこかで費用にしないと
借方が埋まりません。科目は税理士の指定どおり「**販売促進費**」、
計上は**付与時ではなく消費時**（付与時にすると、使われずに失効したボーナスまで
費用になってしまうため）。

そのうえで**税理士の推奨は純額処理**でした（第4回回答）。

> 「両建てにすると**課税売上高が水増しされ、免税判定と簡易課税判定が
> 実態より早く到来します。**」

取引ごとの仕訳を純額で作ると利用料の売上が取引単位で歯抜けになって追いにくいので、
①取引ごとの仕訳は両建てで素直に作り、②区分「**純額調整**」の行で無償コイン起因の
利用料を売上から落とす、という2段構えにしてあります。
按分式は `accounting_revenue()` の「内数（控除の候補）」と同じ
`fee_coins × bonus_coins / coins` です。

</details>

## 3. なぜこの作りにしたか

### 3-a. 元帳から引いている（集計値からは引いていない）

仕訳は `coin_transactions` / `payouts` / `coin_lot_consumptions` から作っています。
`coin_wallets`（残高のキャッシュ）は使っていません。

**残高は事故で狂いますが、元帳は 0044 で追記専用になっていて狂いません。**
狂ったキャッシュから仕訳を作ると、帳簿のほうが現実に合わなくなります。

### 3-b. 突合を必ず通す

`accounting_journal_check()` が、生成した仕訳を科目ごとに積み上げて
元帳の残高と比べます。**合わないことに気づけない自動化は、手作業より危険です。**
数字はもっともらしく出るので、取り込んだ後になって気づくことになります。

### 3-c. 無償コインを前受金に混ぜない

税理士の第1回回答から一貫している点です。**現金を受け取っていないものを
負債に立ててはいけません。** 資金決済法の適用除外を選択している現在、
分別対象額の計算にも直接効きます。

## 5. 会計ソフトを選ぶときに見るところ

まだ決めていない場合の判断材料です。**どれを選んでもこの手順は変わりません**
（3社とも汎用仕訳のCSVインポートを備えており、弥生形式を読めます）。

| | 向いている点 | 引っかかる点 |
|---|---|---|
| やよいの青色申告 オンライン | 仕訳インポートが素直。この文書の税区分名がそのまま通る | 銀行・カードの自動連携は他社のほうが強い |
| freee | 銀行・カード連携が強く、**経費側の手入力が減る** | 独自の「取引」概念があり、仕訳を直接入れる操作が少し遠い |
| マネーフォワード クラウド確定申告 | 連携が強く、仕訳の直接入力もしやすい | — |

**経費側（1-g）の手間で選ぶのが実際的です。** 売上側はどれを選んでも
CSVを取り込むだけになります。
